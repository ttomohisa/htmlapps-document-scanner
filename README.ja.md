# 提出PDFスキャナー

[English](README.md)

紙をスマホで撮影し、**台形補正 → 読みやすさ調整 → 複数ページ整理 → 提出条件に合わせたPDF化**までブラウザーだけで完結する、スマホ最優先の書類スキャナーです。

## できること

- 背面カメラ優先の撮影。QR Readerと同系統のカメラUIで、ライト、カメラ切替、カメラON/OFFに対応。ズームは端末のカメラズームを優先し、非対応端末でも最大4×のデジタルズームを利用可能。
- 書類が止まったら撮る「自動撮影」オプション。
- 端末内で四隅を自動推定し、外れても指で4点を直接修正。
- 台形補正と「自動 / カラー / グレー / 白黒」フィルター。
- 複数ページをカードで管理し、そのままドラッグして並べ替え。
- スマホはページカードを3列表示。
- スマホは撮影画面を大きく使い、上部の電源アイコンでカメラを必要なときだけON/OFF。下部の **スキャン / ページ / PDF** ナビで主要画面を切り替え。
- **1MB以下 / 2MB以下 / A4 / 白黒**の提出条件プリセット。
- 出力ファイル名を自由に入力可能。`.pdf` を省略した場合は自動で付与。
- PDFをブラウザー内だけで生成し、保存またはOSの共有シートへ渡す。
- 画像アップロード、解析、CDN、外部フォント、実行時API通信なし。
- 日本語 / English を同じ単一HTML内で切替。

## 「PDFスキャナー」ではなく「提出用PDFメーカー」

単に写真をPDFにするだけではなく、実際の提出時に詰まりやすいところをまとめて解決する設計です。

- 写真が斜め → 四隅検出と台形補正
- 3枚を1ファイルにしたい → 複数ページ整理
- A4指定 → A4ページへ配置
- 1MB / 2MB以下 → JPEG品質と解像度を必要な分だけ自動調整
- 白黒指定 → PDF生成時にまとめて白黒化
- 本当に条件内か不安 → 生成後に実容量を表示して提出前チェック

## 使い方

`dist/index.html` を開くとカメラ起動を自動で試みます。GitHub PagesなどHTTPSでの利用に加え、PC版Chromeでは `file://` で直接開いた場合もカメラ権限が許可されていれば撮影を試みます。利用できない場合は画面内の再試行または **画像を追加** を使えます。

1. 必要なときだけカメラをONにし、紙全体が写るように撮影、または既存画像を追加。ズームは画面上のスライダー、スマホではピンチ操作でも調整できます。
2. 自動認識された四隅を確認。必要なら丸いハンドルを指で移動。
3. 「自動 / カラー / グレー / 白黒」を選んでページ追加。
4. ページカードを直接ドラッグして順番を変更。
5. 出力ファイル名を入力し、「1MB」「2MB」「A4」「白黒」など提出条件を選択。
6. PDF作成後、実際の容量と提出前チェックを確認して保存・共有。

## ビルド

`htmlapps-template` の構成に準拠しています。`dist/` は直接編集せず、`src/index.template.html` を変更して再生成します。

Windows PowerShell:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\build-standalone.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-repository.ps1
```

生成物:

- `dist/index.html` — 読みやすい完全内包版
- `dist/index.self-extract.html` — gzip自己解凍版
- `dist/build-manifest.json` — ビルド情報
- `dist/.nojekyll` — GitHub Pages向け

## プライバシー

作業中の画像とPDFはブラウザーのメモリ内だけで扱います。CSPは `connect-src 'none'` で、v1.0では外部ランタイム依存もありません。ページ内容はあえて永続保存しないため、**再読み込み・タブを閉じると作業中データは消えます**。

## 注意事項

カメラ利用可否はブラウザーと権限設定に依存します。このアプリは `file://` を理由にカメラ起動を止めず、PC版ChromeでもQR Readerと同様に起動時から `getUserMedia` を試します。カメラは画面内の電源ボタンで停止でき、停止時はMediaStreamのトラックを解放します。失敗時は理由に応じた案内と再試行、画像追加を表示します。

四隅の自動認識は、白い机、強い影、低コントラスト、光沢などでは外れることがあります。自動認識だけに依存せず、必ず4点を手動修正できる設計にしています。

容量制限を選ぶと画質や解像度を下げる場合があります。小さい文字を含む提出書類は、生成後のPDFを拡大して読めることを確認してください。
